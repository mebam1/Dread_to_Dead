## 4. 한 턴

1. 주사위 3개 공개 → 하나 확정·선택 효과 처리.
2. 액티브·탈출구 준비. **확정 전 액티브는 전부 불가**.
3. 예언가 사용 시 비용 4(강화 3)를 지불하고 같은 턴의 **굴림 단계**로 복귀. 다시 굴려 확정한 뒤 액티브·이동 가능.
4. 이동 실행. 실제 순서대로 탈출구 → 유인/통과/도착을 판정. 금고는 남은 이동을 중단하고 그 층 도착 효과를 실행.
5. 실제 도착 괴이에 따개비 방어 전달. 도착 효과를 처리하며 공포마다 심장 판정.
6. 살아 있는 손님에게 보유 예언만큼 공포를 한 번 가한 뒤 예언 -1.
7. 손님 공격을 개별 타격·대리 수신·방어·공략도·파훼 순서로 처리.
8. 방어·대리 피격 정리 → 비활동 판정 → 생존 괴이 봉인/화재 각각 -1 → 다음 턴.

봉인 3은 부여한 턴을 포함해 세 턴의 기능을 막는다. 리롤은 위 6~8단계를 실행하지 않고 턴 번호·상태·횟수·이미 쓴 방어·봉인을 되돌리지 않는다.

주사위 조건은 사마라 조작 뒤 최종 확정 눈이다. 금고가 이동을 짧게 끊어도 눈 자체는 바꾸지 않는다. 사마라는 눈 1에서 사용 불가다.

예언으로 마지막 심장을 제거하면 반격·후속 감소를 중단한다. 새 손님은 자원 0으로 입장한다. 시선의 주인+도 처치 후 불안 +1을 다음 손님에게 넘기지 않는다.

## 5. 텍스트 진행과 정보 경계

- Node.js 20 이상, 외부 패키지 없이 독립 디렉터리에서 실행한다.
- 저장은 진행자 장부다. 플레이어는 CLI의 공개 view·map·현재 눈 미리보기만 읽는다. 미방문 재고·미래 눈·숨은 판정 상태를 원시 저장에서 읽고 선택하지 않는다.
- 선택 명령에는 이유를 남긴다. 실패한 명령은 저장하지 않으며 기존 파일을 new로 덮어쓰지 않는다.
- 미리보기는 사본에서 실제 판정을 사용한다. 예언가를 계획한 미리보기는 비용 차감과 굴림 복귀까지만 보이며 새 난수·새 눈은 공개하지 않는다.
- 기록은 개체 ID별 획득 출처(시작/상점/무료/이벤트), 배치·강화·수치 기여·파괴를 연결한다.
- checkpoint와 control 분기는 원본을 보존한다. 과거 체크포인트에서 다시 진행한 비교는 정상 첫 선택과 별도 분류한다.
