# Dread-to-Dead — 사용자 프로토타입 3

[사용자 설정 3 v1.1](../mvps/mvp-config-user-3.md)과 [모험](../ui/adventure.md)·[준비](../ui/prepare.md)·[전투](../ui/battle.md) 화면 명세를 구현한 로컬 웹 게임입니다. 3막의 경로 선택부터 구매·배치·전투·보상, 최종 승리·패배·재시작까지 연결됩니다. 게임 소스와 검증 자료는 이 디렉터리 안에서 독립적으로 실행되며 외부 패키지를 설치하지 않습니다.

## 실행

Node.js 20 이상이 설치된 Windows에서 [play.cmd](play.cmd)를 더블 클릭합니다. 서버와 기본 브라우저가 열립니다. 서버 창을 닫으면 종료됩니다.

터미널에서 실행하려면 이 디렉터리로 이동한 뒤 다음 명령을 사용합니다.

```powershell
npm start
```

[게임 열기](http://127.0.0.1:4173) — HTML 파일을 직접 여는 대신 로컬 서버 주소를 사용하세요. 종료는 `Ctrl+C`입니다. user-1·user-2 서버가 같은 포트에 열려 있다면 먼저 종료합니다. 다른 포트가 필요하면 `$env:PORT = 4183`을 지정한 뒤 실행합니다.

진행 중인 판은 메모리에만 보관됩니다. 새로고침하면 새 판으로 시작합니다. 안내·연출 옵션과 설명 확인 이력만 브라우저에 저장합니다. 동일한 브라우저와 주소의 기존 user-2 옵션은 처음 실행할 때 이어받고, user-3의 새 개념 설명은 별도로 기록합니다.

## 한 판의 흐름

1. 지도에서 연결된 노드를 살펴본 뒤 **이 노드 방문**을 누릅니다. 각 막은 20개 노드 중 8개를 방문하며, 7번째 공통 회복과 8번째 보스를 반드시 거칩니다.
2. 영혼으로 상점의 괴이를 구매하고 호텔을 배치합니다. 상점에서만 6층부터 최대 10층까지 증설할 수 있습니다. 증설 비용은 4·6·8·10이며 구매 전에 경로와 잔액을 비교합니다.
3. 일반 전투는 손님 3명, 엘리트·보스는 1명입니다. 주사위 3개를 굴려 하나를 고르고, 직접 효과와 탈출구를 준비한 뒤 이동합니다. 처치한 일반 손님 다음에는 자동으로 새 손님이 들어옵니다.
4. 완승하면 서로 다른 기본 괴이 3개 중 하나를 반드시 획득합니다. 엘리트에서는 이후 특수 주사위 하나를 교체하거나 건너뜁니다. 보스는 주사위를 지급하지 않습니다.
5. 보스를 처치하고 괴이 보상을 받으면 다음 막으로 갑니다. 3막 보스의 마지막 심장을 제거하면 전투 승리가 잠기고, 마지막 괴이 보상을 고르면 결과 화면이 열립니다.

초기 상태는 영혼 4, 6층, 괴이 4개, 일반 주사위 3개입니다. 파훼 토큰은 다음 손님·노드·막으로 이월됩니다. 전투 준비 최초 진입 시 공략도와 보호만 초기화하고 직접 사용 잔량을 복구합니다. 파괴된 개체는 사라지며 같은 종류를 새로 획득할 수 있습니다.

일반·엘리트 탈출은 지금까지 처치한 손님의 영혼만 남기고 노드를 마칩니다. 모든 보스의 탈출, 배치된 괴이 전멸, 포기는 패배입니다. 보관함에 괴이가 있어도 전투 중 마지막 배치 괴이가 파괴되면 패배합니다.

## 화면과 조작

- **지도:** 아래에서 위로 진행합니다. 호버·키보드 초점·첫 탭으로 노드를 검토하고 방문 버튼으로 확정합니다. 손님 정보는 미리 공개하며 상점 재고·이벤트·발견물은 방문 후 공개합니다. 이전 막은 열람만 가능합니다.
- **준비:** 1280×720을 기준으로 최대 10층과 지하 설비를 한 화면에 표시합니다. 호텔은 스크롤하지 않고 오른쪽 노드·보관함과 긴 상세만 내부에서 스크롤합니다. 초대 손님 초상에서 공격·한계·심장·보상을 확인합니다. 구입·보관 중 괴이는 카드, 배치 뒤에는 작은 호텔 복도로 보입니다.
- **배치:** 카드를 층에 드래그하거나 **배치하기 → 대상 층**을 누릅니다. 층끼리 교환하고 보관함으로 회수할 수 있습니다. 클릭·터치·키보드 조작을 함께 제공합니다. 미확정 선택은 `Esc` 또는 취소로 되돌립니다.
- **회복:** 전체 예산 2개를 손상된 생존 개체에 배분하거나, 개체 하나를 강화합니다. 배분·대상 검토 중에는 상태가 바뀌지 않으며 확정하면 노드를 마칩니다. 남은 회복량을 포기하거나 아무것도 받지 않고 떠날 수 있습니다.
- **강화:** 개체 이름에 `+`가 붙고 카드 수치가 갱신됩니다. 회복을 동반하지 않으며 새로 구매한 같은 종류까지 강화하지 않습니다. 호출벨+의 초기 사용 3회는 다음 전투 준비 때 적용됩니다.
- **전투:** 호텔 전체 위치와 층 높이를 고정하고 오른쪽 엘리베이터 조작반에서 최종 결과·주사위·실행 조작을 확인합니다. 별도 미니맵 없이 호텔 본체에 실제 손님 위치, 통과·도착과 손실을 표시합니다. 주사위 검토·대상 선택·실제 이동·구매 연출 중에도 호텔 카메라는 움직이지 않습니다.
- **직접 사용:** 사용 가능한 층에 노란 테두리가 나타납니다. 호출벨은 층을 누르면 즉시 사용합니다. 보호·수리는 사용 괴이의 층을 누른 후 호텔 본체의 대상 층을 검토하고 확정합니다. 호버·키보드 초점은 가상 예고만 표시하고 클릭·확정 키가 비용을 소비합니다. 터치는 첫 탭으로 검토, 두 번째 탭으로 확정합니다. 정보 아이콘은 카드만 엽니다.
- **예고:** 호텔 옆 직선·순환 화살표와 방문 순번으로 이동 경로를 보여주고 각 방문에서 실제로 얻거나 소비하는 불안·공포·충전을 표시합니다. 재방문은 별도 순번으로 구별하고 처치·탈출 이후 경로는 실행되는 것처럼 그리지 않습니다. 오른쪽에는 도착, 공포, 심장 제거, 반격과 토큰 손실 요약을 유지합니다. 상세에서는 선택 효과 → 통과 → 도착 → 타격 순서를 확인합니다. 무작위 비활동 패널티는 가능한 손실로 따로 표시합니다.
- **읽기 전용:** 괴이 보상, 주사위 교체 비교, 회복·강화·계약 대상 검토 중에는 호텔 배치를 잠급니다. 선택 취소는 비용이나 보상을 발생시키지 않습니다.
- **안내와 기록:** 첫 등장 설명은 옵션에서 끌 수 있습니다. 용어와 괴이 정보는 다시 열어 볼 수 있고, 전체 기록은 JSON으로 내려받을 수 있습니다.

호텔의 기본 검토 크기는 1280×720입니다. 최대 10층을 44px 높이의 행으로 배치하고, 6층일 때는 같은 행 높이로 아래에서부터 실제 6층만 표시합니다. 폭 1080px 미만에서는 글자와 정보 버튼을 줄이거나 숨기지 않고 가로로 화면을 탐색합니다. 호텔 층을 찾기 위한 세로 스크롤은 없습니다.

## 검증과 확인 범위

```powershell
npm test
npm run verify:campaign
node verify-campaign.mjs --conservative
```

규칙 검사는 강제 눈·진단 상태를 사용하는 경계 검사입니다. 오프라인 UI 검사는 DOM 대역에서 HTML과 조작 상태 전환을 확인합니다. 최종 보스 처치 → 필수 보상 → 승리와 패배·재시작도 이 방식으로 검사합니다. 실제 브라우저의 렌더링·입력 장치·연출 품질을 확인한 검사는 아닙니다.

2026-11-01 기준 규칙 50개와 오프라인 UI 35개, 총 **85개 검사 통과**. HTML·앱 스크립트·엔진·스타일의 로컬 HTTP 200 응답을 확인했습니다. 서버의 정적 파일 처리와 `combat-base.mjs`를 포함한 ES 모듈 MIME 형식도 별도 검사했습니다. 이번 UI 개정에서는 본체 층 대상 선택·정보 버튼 비실행·순환/재방문 화살표·실제 효과량·탈출 이후 경로 중단·연출 중 카메라 불변을 확인했습니다. CSS 높이 합산은 1280×720에서 전투 695px, 준비 662px입니다. 이 계산과 DOM 대역 검사는 실제 브라우저 픽셀 검사를 대신하지 않습니다. 브라우저 접근 제한으로 실제 화면과 연출의 시각 점검은 수행하지 못했습니다.

캠페인 자동 플레이는 실제 공개된 눈과 정상 API만 사용합니다. 강제 자산·눈, 미래 굴림 탐색, 수치 변경, 성공하는 난수만 선택하는 방식은 사용하지 않았습니다. 두 고정 정책으로 지정 번호 31001·31002·31003을 각각 실행한 결과를 모두 보존했습니다.

| 고정 정책 | 난수 번호 | 결과 | 완료 방문 | 턴 수 | 처치 |
|---|---:|---|---:|---:|---:|
| 장비·선택 노드 우선 | 31001 | 2막 엘리트에서 패배 | 11 / 24 | 68 | 8 |
| 장비·선택 노드 우선 | 31002 | 2막 엘리트에서 패배 | 11 / 24 | 54 | 8 |
| 장비·선택 노드 우선 | 31003 | 2막 엘리트에서 패배 | 11 / 24 | 42 | 8 |
| 엘리트 회피 | 31001 | 2막 일반 전투에서 패배 | 11 / 24 | 66 | 15 |
| 엘리트 회피 | 31002 | 3막 첫 일반 전투에서 패배 | 16 / 24 | 67 | 15 |
| 엘리트 회피 | 31003 | 3막 첫 일반 전투에서 패배 | 16 / 24 | 77 | 16 |

자동 정책으로 완주 승리를 입증하지 못했습니다. 두 실행에서 앞선 두 막의 보스 처치와 3막 진입을 확인했지만, 이것만으로 사람이 느끼는 난이도나 승리 가능성을 단정할 수 없습니다. 설정 수치를 유지했으며 후반 손상 누적과 회복·구매 선택을 실제 플레이에서 살펴볼 필요가 있습니다.

전체 요약은 [validation/summary.json](validation/summary.json), 각 판의 경로·행동·개체 상태는 같은 디렉터리의 `campaign-*.json`에 있습니다. 자동 실행 시간은 사람의 플레이 시간 추정치가 아닙니다.

## 파일

- `engine.js`: 모험 지도, 노드 권한, 경제·회복·강화·보상, 캠페인 경계
- `combat-base.mjs`: 순환 이동, 주사위, 효과·공격·탈출, 예고 공통 판정
- `app.js`: 화면, 조작, 설명·기록, 사건 순서에 따른 전투 연출
- `styles.css`: CSS 도형 복도·카드·기계·지도·미니맵과 반응형 배치
- `server.mjs`, `play.cmd`: 의존성 없는 로컬 실행
- `engine.test.js`, `app-view.test.js`, `verify-campaign.mjs`: 경계·화면 계약·정상 캠페인 검증
